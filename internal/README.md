# internal (RAGE Multiplayer)

Внутренний чит для RAGE MP: DLL, которая мапится в GTA5.exe. Оверлей рисуется
из перехваченного `Present` (D3D11), игровые данные читаются из памяти
процесса, скрипты выполняются в V8 самого клиента через очередь команд.

Это **user-сборка**. Дев-инструментов здесь нет физически, а не «выключены
флагом»: логгер событий, дампер педов, дампер ресурсов и файловый лог в этом
дереве отсутствуют как исходники.

## Доставка без драйвера

Пейлоад мапится в игру **из юзермода**, драйвер не нужен. `shadow_injector`
читает `shadow_internal.dll`, мапит её в GTA5.exe (секции, релокации, импорты)
и запускает `DllMain` на новом потоке. Ничего не грузится в ядро, поэтому не
нужно отключать ни HVCI, ни список блокировки уязвимых драйверов, ни Secure
Boot — всё это касается только загрузки драйверов, а мы его не загружаем.

```text
shadow_injector.exe            # инжект в уже запущенную GTA5
shadow_injector.exe --watch    # ждать запуска GTA5 и инжектить при старте
```

`--watch` повторяет тайминг ядерного пути: ждёт, пока в процессе появятся
`dxgi`/`d3d11`, и мапит до загрузки `multiplayer.dll`. Инжект в уже живую игру
тоже работает, но резолверу имён нужно несколько секунд на прогрев кэша.

Инжектору нужны права на чтение/запись памяти GTA5 (запуск от администратора).

## Сборка

```bash
cmake -S . -B build -A x64
cmake --build build --config Release
```

На выходе `build/Release/shadow_internal.dll` и `build/Release/shadow_injector.exe`.

Требуется MSVC (Build Tools 2022 достаточно) и Windows SDK. Сторонние
зависимости вендорены в `third_party/`, качать при сборке ничего не нужно.

Три вещи в настройках сборки неочевидны и ломают линковку, если их убрать:

- CRT линкуется статически. Ручной маппинг обходит загрузчик Windows, поэтому
  нельзя рассчитывать, что CRT-DLL вообще разрешится в целевом процессе.
- Библиотеки CRT перечислены явно (`libcmt`, `libucrt`, `libvcruntime`).
  Директив по умолчанию не хватает: C-половина статического CRT сама не
  подтягивается, это видно как неразрешённые `strtoul` и
  `__stdio_common_vsprintf_s`.
- Точка входа — `DllMain` напрямую (`/ENTRY:DllMain`). В вручную замапленном
  образе нет CRT-стартапа, который вызвал бы её сам.

## Что пишется на диск

Лога нет. Дампов нет. Проверяется не на слово: в собранной DLL нет ни строки
`cheat_log`, ни путей дампов — можно поискать в бинарнике.

Чит трогает три файла, и все три — данные самого пользователя:

| Файл | Зачем |
|---|---|
| `C:\RAGEMP\config*` | Настройки меню: сохранение и загрузка конфигов |
| `C:\RAGEMP\user_scripts.bin` | Библиотека пользовательских скриптов |
| `C:\RAGEMP\cloud.session` | Токен сессии, читается один раз при инжекте |

Если и это не нужно — убирать надо `Menu/MenuConfig.cpp`,
`Features/ScriptBridge.cpp` и `Features/CloudStorage.cpp`, но вместе с ними
уедут сохранение настроек, библиотека скриптов и авторизация.

## Структура

| Папка | Что там |
|---|---|
| `src/Main` | Хуки `Present`/`ResizeBuffers`/`SetFullscreenState`, кадровый цикл |
| `src/SDK` | Оффсеты, игровые структуры, проекция мира на экран, кадровый контекст педов |
| `src/Features` | Аимбот, визуалы, скелеты, радар, скрипт-мост, серверные инструменты |
| `src/Menu` | Меню, страницы, тема, конфиги, ESP-редактор |
| `src/imgui` | Dear ImGui с локальными правками под оверлей |
| `src/Helpers` | Хуки DXGI/D3D11 и вспомогательный код рендера |
| `src/Memory` | Поиск по паттернам |
| `src/assets` | Шрифты, иконки оружия, меш превью |
| `injector` | Юзермод-инжектор `shadow_injector` — доставка без драйвера |
| `third_party/minhook` | MinHook, вендорен |

## Флаги сборки

`src/SDK/RageBuildFlavor.h` фиксирует флавор дерева: `RAGEMP_DEV_BUILD`,
`RAGEMP_EVENT_LOGGER` и `RAGEMP_DEV_UI` прибиты к нулю. Это сделано намеренно —
включить их обратно нечем, реализации в дереве нет, и сборка просто не
слинкуется. Диагностика живёт в дев-дереве.
