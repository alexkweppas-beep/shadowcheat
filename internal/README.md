# internal (RAGE Multiplayer)

Внутренний чит для RAGE MP: DLL, которая мапится в GTA5.exe. Оверлей рисуется
из перехваченного `Present` (D3D11), игровые данные читаются из памяти
процесса, скрипты выполняются в V8 самого клиента через очередь команд.

Это **user-сборка**. Дев-инструментов здесь нет физически, а не «выключены
флагом»: логгер событий, дампер педов, дампер ресурсов и файловый лог в этом
дереве отсутствуют как исходники.

## Доставка без драйвера

Production-пейлоад скачивает и manual-map'ит защищённый `repo-launcher`.
Он передаёт в `DllMain::lpReserved` одноразовый bootstrap с product-scoped
ticket и сразу освобождает его после старта. Именованная shared-memory секция
с постоянным JWT для internal больше не используется.

Standalone `shadow_injector` оставлен только для разработки и по умолчанию не
собирается. Он не входит в shipping-каталог.

## Сборка

```bash
cmake -S . -B build -A x64 \
  -DSHADOW_VMP_ROOT="D:/tools/VMProtect" \
  -DSHADOW_BUILD_TAG="release-2026-09"
cmake --build build --config Release
```

Release по умолчанию собирается с SDK-маркерами и сразу проходит через
`VMProtect_Con`. На выходе `build/Release/shadow_internal.dll` уже защищён;
необработанная DLL удаляется fail-closed скриптом. Если консоль завершилась с
ошибкой или предупреждением, сборка считается неуспешной и сырой файл не
маскируется под релиз.

Для локальной отладки без протектора надо указать явно:

```bash
cmake -S . -B build-dev -A x64 -DSHADOW_ENABLE_VMP=OFF
```

Для локальной диагностики можно явно сохранить сырой файл:
`-DSHADOW_KEEP_VMP_RAW=ON`. Такой файл нельзя отдавать пользователям.

Персональный watermark, заранее созданный в VMProtect, задаётся через
`-DSHADOW_VMP_WATERMARK=<имя>`. Для раздачи лучше собирать отдельный watermark
на пользователя: он не запрещает дамп, но позволяет определить источник слива.

Development-инжектор включается отдельно:
`-DSHADOW_BUILD_DEV_INJECTOR=ON`.

Production-каталог из 32 cohort-вариантов и on-demand JS собирается одной
командой:

```powershell
.\scripts\Build-ProtectedVariants.ps1 `
  -VmpRoot "D:\tools\VMProtect" `
  -OutputRoot "..\repo-website\back\backend\products\ragemp\variants" `
  -Count 32
```

Каждый вариант получает отдельные `SHADOW_VARIANT_ID/SEED`, VMProtect output
и SHA-256. Backend стабильно выбирает cohort через HMAC пользователя/HWID,
после чего патчит персональный customer tag. Quant/FiveRP/Ukraine JS в DLL не
входят: скрипт сборки экспортирует их в соседний `features/`, а клиент получает
персонализированный AES-GCM bundle только по действующему launch ticket.

Требуется MSVC (Build Tools 2022 достаточно), Windows SDK, Python 3 и пакет
`cryptography` для упаковки feature bundles. C/C++ зависимости вендорены в
`third_party/`.

Три вещи в настройках сборки неочевидны и ломают линковку, если их убрать:

- CRT линкуется статически. Ручной маппинг обходит загрузчик Windows, поэтому
  нельзя рассчитывать, что CRT-DLL вообще разрешится в целевом процессе.
- Библиотеки CRT перечислены явно (`libcmt`, `libucrt`, `libvcruntime`).
  Директив по умолчанию не хватает: C-половина статического CRT сама не
  подтягивается, это видно как неразрешённые `strtoul` и
  `__stdio_common_vsprintf_s`.
- Точка входа — статический CRT (`/ENTRY:_DllMainCRTStartup`), который
  инициализирует runtime и затем вызывает `DllMain`. Инжектор выполняет TLS
  callbacks защищённого образа перед точкой входа.

## Что пишется на диск

Лога нет. Дампов нет. Проверяется не на слово: в собранной DLL нет ни строки
`cheat_log`, ни путей дампов — можно поискать в бинарнике.

Чит трогает три файла, и все три — данные самого пользователя:

| Файл | Зачем |
|---|---|
| `C:\RAGEMP\config*` | Настройки меню: сохранение и загрузка конфигов |
| `C:\RAGEMP\user_scripts.bin` | Библиотека пользовательских скриптов |
| `C:\RAGEMP\cloud.session` | Токен сессии, читается один раз при инжекте |

Если и это не нужно — убирать надо `Menu/MenuConfig.cpp`,
`Features/ScriptBridge.cpp` и `Features/CloudStorage.cpp`, но вместе с ними
уедут сохранение настроек, библиотека скриптов и авторизация.

## Структура

| Папка | Что там |
|---|---|
| `src/Main` | Хуки `Present`/`ResizeBuffers`/`SetFullscreenState`, кадровый цикл |
| `src/SDK` | Оффсеты, игровые структуры, проекция мира на экран, кадровый контекст педов |
| `src/Features` | Аимбот, визуалы, скелеты, радар, скрипт-мост, серверные инструменты |
| `src/Menu` | Меню, страницы, тема, конфиги, ESP-редактор |
| `src/imgui` | Dear ImGui с локальными правками под оверлей |
| `src/Helpers` | Хуки DXGI/D3D11 и вспомогательный код рендера |
| `src/Memory` | Поиск по паттернам |
| `src/assets` | Шрифты, иконки оружия, меш превью |
| `injector` | Юзермод-инжектор `shadow_injector` — доставка без драйвера |
| `third_party/minhook` | MinHook, вендорен |

## Флаги сборки

`src/SDK/RageBuildFlavor.h` фиксирует флавор дерева: `RAGEMP_DEV_BUILD`,
`RAGEMP_EVENT_LOGGER` и `RAGEMP_DEV_UI` прибиты к нулю. Это сделано намеренно —
включить их обратно нечем, реализации в дереве нет, и сборка просто не
слинкуется. Диагностика живёт в дев-дереве.
